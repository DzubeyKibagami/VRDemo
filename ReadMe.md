## README

### Версия Unreal Engine

Проект разрабатывался на Unreal Engine версии: 5.8.1

### Запуск

Для открытия проекта с помощью Rider:

- Запустите JetBrains Rider
- Нажмите Open (Открыть) на стартовом экране или выберите в меню File > Open
- Найдите папку проекта и выберите файл с именем VRDemo.uproject

Для открытия проекта с помощью Visual Studio (2022):

- Зайдите в папку проекта
- Нажмите правой кнопкой мыши по файлу VRDemo.uproject
- Выберите пункт Generate Visual Studio project files (Создать файлы проекта Visual Studio)
- Дождитесь окончания генерации и откройте появившийся файл (.sln или .slnx)

Для сборки С++ проекта с помощью Rider:

- Убедитесь, что в верхнем выпадающем списке конфигураций выбрана нужная конфигурация сборки (бычно Development Editor для работы в редакторе) и целевой проект
- Нажмите на иконку молотка (Build) на панели инструментов в верхнем правом углу или используйте горячие клавиши (Ctrl + F9 (в ОС Windows/Linux))
- Дождитесь окончания процесса в панели Build в нижней части экрана.
- Для запуска проекта прямо из среды разработки нажмите клавишу Ctrl + F5 или кнопку Run

Для сборки С++ проекта с помощью Visual Studio:

- Найдите панель инструментов сверху и выберите нужный режим в выпадающем списке конфигураций (обычно Development Editor для работы в редакторе)
- Убедитесь, что для целевой платформы выбрано значение Win64 (или ваша текущая платформа)
- Запуск сборки: в верхнем меню выберите Сборка > Собрать решение (или нажмите горячие клавиши Ctrl + Shift + B)
- Дождитесь окончания процесса в окне «Вывод» (Output)
- Для запуска проекта прямо из среды разработки нажмите клавишу F5 или кнопку Локальный отладчик Windows

После первого открытия проекта в Unreal engine editor

- Так как тестовая сцена использует запеченный свет, необходимо будет построить локально light map. Для этого:
  - Найдите в верхнем меню раздел билд и выберете его
  - Выберете пункт Build Lighting Only и дождитесь окончания процесса

Для запуска VR Preview режима (на примере Oculus Quest):

Подготовка шлема и ПК
- Скачайте, установите и откройте приложение Meta Horizon Link на компьютере
- Подключите шлем Oculus Quest к ПК по кабелю USB или через Quest Link / Air Link в самом шлеме
- Добавьте гарнитуру (шлем и контроллеры) на вкладке устройства. Установите с ними связь
- Убедитесь, что шлем видит компьютер и вы находитесь в виртуальном пространстве Meta Horizon Link

Запуск VR Preview
- Для шлема: проверте подключение к сети wifi (оно должно быть активно), после этого подключитесь к PC с помощью Quest Link (в окне быстрых настроек)
- Нажмите на кнопку с вертикальным многоточием рядом с кнопкой Play (Играть) на панели инструментов
- Выберите пункт VR Preview (если шлем подключем правильно она должна быть активна)
- Картинка откроется в шлеме Oculus Quest

### Управление

На примере Oculus Quest:
 
- Перемещение вперед: движение вперед стиком на правом контроллере
- Поворот: движения в право/лево стиком на левом контроллере
- Выделение объекта: наведение лучом исходящим из правого контроллера на объект
- Схватить объект: выделить объект и Grip на правом контроллере
- Отпустить объект: отпустить Grip на правом контроллере
- Вращать объект - Tho handed interaction: выделить объект/схватить объект, перемещать правый стик влево/вправо - поворот по Yaw, перемещать левый стик вверх/вниз поворот по Pitch
- Удалить объект: выделить объект/схватить объект, нажать на нижнюю кнопку (А) на правом контроллере
- Открыть/закрыть UI меню: нажать на верхнюю кнопку (B) на правом контроллере
- Добавить объект: открыть UI меню, выделить объект, навестись левым контроллером на кнопку add focused object и нажать триггер на левом контроллере
- Удалить объект из UI: открыть UI меню, выделить объект, навестись левым контроллером на кнопку remove focused object и нажать триггер на левом контроллере

### Архитектура

Основные C++ классы / компоненты:
- **Pawn**
  - **VRPawn** - основной класс, являющийся представлением игрока в VR пространстве. Отвечат за визуальную репрезентацию игрока, его перемещение в виртуальной среде и реакцию на поступающий от устройств инпут. Так же обрабатывает данные, поступающие от сенсоров об окружающем мире
  - **VRAnimationHandComponent** - компонент отвечающий за визуальное представление контроллеров в VR пространстве и изменение их визуального состояния в зависимости от инпута
  - **VRMovementComponentBase** - базовый компонент для реализации модульной системы перемещение игрока в VR пространстве. На его основе строятся компоненты, реализующие различную логику и стратегию перемещения игрока. В рамках проекта показан пример реализации такого подхода (телепорт). Как пример на его основе можно реализовать компонент плавного перемещения игрока и заменить им текущий в Pawn, таким образом поменяв схему перемещения
  - **VRTeleportMovementComponent** - компонент, реализующий логику перемещения Pawn в VR пространстве с помощью патерна телепорта и сегментный поворот (в градусах)
  - **VRHandAnimInstance** - класс, отвечающий за обработку анимационного стейта VRAnimationHandComponent. Для оптимизации game thread вычисления в нем вынесены в отдельный поток
- **Logs**
  - **VRDemoLog** - класс, в котором вводится отдельная категория логирования для отладочной информации проекта
- **Interaction**
  - **VRInteractionObjectInterface** - класс интерфейса, являющийся основой для определения интерактивного объекта и взаимодействия с ним. Интерактивным объектом может быть как отдельный Actor класс, так и любой его компонент плюс их комбинация. Реализация интерфейса позволяет использовать его как в C++ коде так и в Blueprint. Использование такого подхода позволяет очень гибко создавать и собирать интерактивные объекты. Например:
    - Интерактивный объект как отдельный actor, который реализует кастомную логику на общем уровне
    - Интерактивный объект как отдельный компонент. Можно использовать, например, для реализации отдельных зон интеракции с одним Actor, как контейнер обобщенной логики интерации для переноса между существующими акторами и т.д.
    - Комбинация actor и компонентов для реализации сложного интерактивного объекта. Например Actor, в котором необходимо сначала повзаимодействовать с его отдельными составляющими (компонентами), прежде чем перейти к манипуляция с основным телом
  - **VRSimpleInteractionActor** - класс, представляющий собой пример реализации шаблонного интерактивного объекта на уровне Actor 
  - **VRInteractionStatics** - класс, реализующий общие статические функции для работы различных компонентов интерактивной системы
  - **VRInteractionObjectsSubsystem** - класс, реализующий подсистему, в задачу которой входит сбор данных обо всех интерактивных объектах в мире и предоставления информации по ним. В данном проекте востребована общая информация об их количестве, однако позже ее можно использовать и для многих других целей. Например получения подгрупп объектов (определенного типа), получения списка всех интерактивных объектов в мире и т.д.
  - **VRWidgetInteractionComponent** - компонент, реализующий логику взаимодействия игрока с UI и визуальную репрезентацию указателя на UI элементы
  - **VRInteractionSensorComponent** - базовый класс для реализации модульной системы сенсоров игрока. Задача сенсоров - взаимодействие с игровым миром и сбором информации о нем. На его основе можно собирать сенсоры различных типов, реализующих кастомную логику обнаружения объекта взаимодействия. Например:
    - Дистанционный сенсор, например в виде луча или указки
    - Контактный сенсор, например в виде сферы вокруг визуально репрезентации VR контроллера
    - Тактильный сенсор, например для идентификации взаимодействия с миром отдельными элементами репрезентации VR контроллера (пальцы руки)
  - **VRInteractionRayComponent** - компонент, реализующий дистанционный вид сенсора в виде луча
  - **VRInteractionMenuWidgetComponent** - компонент, реализующий логику обработки меню интерактивного объекта в 3D пространстве и передачи инициализационных данных UI представлению
  - **VRInteractionObjectsWidget** - класс, реализующий UI представление меню интерактивного объекта

Определение интерактивного объекта
- Интерактивный объект определяется на основе данных работы дистанционного сенсора указки, расположенного в районе правого VR контроллера игрока. Результатом работы сенсора является информация об обнаруженном компоненте в мире, а на его основе определяется интерактивный объект - actor либо сам компонент, реализующие интерфейс интерактивного объекта

Состояние взаимодействия с объектом
- Состояние взаимодействия с интерактивным объектом хранится в компоненте сенсора. Он содержит информацию о текущем определенном компоненте, через него можно получить объект взаимодействия, у которого при необходимости можно запросить его текущий статус

Добавление нового типа объекта

Благодаря гибкой архитектуре интерактивных объектов, есть различные способы добавления нового интерактивного объекта:
- В данном проекте показан пример реализации интерактивного объекта в виде отдельного шаблонного Actor с комплексной логикой. Для добавления интерактивного объекта на его основе необходимо:
  - Создать экземпляр BP класса нового интерактивного объекта на основе плюсового классса VRSimpleInteractionActor либо как копию существующего BP класса интерактивного объекта. Провести настройку следующих параметров (если создавать новый объект путем копирования существующего BP класса, необходимо выполнить только пункты (1, 2 (опционально) и 4):
    - Указать визуальную репрезентацию объекта - установить static mesh для StaticMeshComponent
    - В качестве материала static mesh установить материал, поддерживающий визуальную подсветку mesh (один из материалов, начинающихся с MI_VRFlatColor_)
    - Указать название параметра материала, отвечающего за интенсивность подсветки (HighlightPower) в поле Material Highlight Param Name
    - Заполнить данные об объекте в поле Object Data
    - Для эмуляции физики со старта объекта, уставновить значение simulate physics (true) и Collision Profile (PhysicsActor)
    - Опционально можно изменить интенсивность подсветки объекта при интеракции - параметр Material HighLight Power
- Другой вариант - реализовать новый кастомный C++ компонент/actor, которые будут реализовывать интерфейс VRInteractionObjectInterface со своей кастомной логикой
- Так же реализация интерфейса позволяет создавать компоненты/actors в BP, реализовывая кастомную логику в них (например для прототипирования и быстрых итераций гипотез)

### C++ / Blueprint

В рамках C++ реализованы:
- Классы и компоненты системы, описанные выше (основная архитектура)
- UI бизнес логика
- Обработка collision case, включая логирование
- Общий функционал для систем интеракции

В рамках Blueprint:
- Схема Input управления и реакция на нее (для быстрой и гибкой смены схемы input при необходимости)
- Взаимодействие элементов интерактивной системы в виде отправки команд в C++
- Логика заполнения визуального представления UI (что бы его можно было поменять в любое удобное время на другое при необходимости)
- Логика шейдера материала подсветки предмета в шейдерном нодовом редакторе
- Тестовая сцена

### VR UI

UI панель меню интерактивного объекта реализована в виде 3D виджета, прикрепленного к области правого контроллера. Виджет рендерится на слегка изогнутую плоскую плоскость. Так как архитектура предполагает использование нескольких сенсоров, виджет связывается на инициализации с одним из них и информацию о текущем объекте получает из него

### Проверка

Проверка, тестирование и отладка проекта проводилась на Oculus Quest 2

### Известные особенности и ограничения

- Так как объекты физические - их можно выкинуть за пределы сцены, после чего они будут бесконечно падать вниз. Обработка этого кейса в рамках данного проекта не производилась
- Добавление объекта в UI представляет собой копирование текущего объекта интеракции. Для большей гибкости
- Удаление объекта в UI так же представляет собой удаление текущего интерактивного объекта
- Период трейса сенсора настраивается параметрически и для оптимизации происходит не каждый кадр. Из-за особенностей реализации тестового визуального эффекта луча можно увидеть артефакты его перестроения при резком повороте
